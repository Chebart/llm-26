# Лабораторная работа 2. RAG по документации PostgreSQL

Локальный помощник находит сведения в документации и отвечает с указанием источников. Поиск объединяет BM25 и Giga-Embeddings, данные хранятся в Qdrant, ответ формирует Qwen через llama.cpp.

## Данные и модели

Корпус состоит из 60 физических страниц, с 30 по 89, [русской документации PostgreSQL 17.11](https://repo.postgrespro.ru/doc/pgsql/17.11/ru/postgres-A4.pdf). Исходный PDF сохраняется целиком, в поиск попадает только выбранный диапазон. Для оценки подготовлены 15 вопросов с эталонными ответами и релевантными страницами.

| Компонент | Реализация |
|---|---|
| Конвертация PDF | PyMuPDF4LLM и PyMuPDF Layout |
| Разбиение текста | Готовые сплиттеры LangChain |
| Dense-эмбеддинги | `ai-sage/Giga-Embeddings-instruct-480M-0826` |
| Поиск по терминам | `Qdrant/bm25` через FastEmbed |
| Хранилище и объединение результатов | Qdrant, HNSW и RRF |
| Генератор | `Qwen3-4B-Instruct-2507`, GGUF Q4_K_M |

Вместо GigaChat из первой лабораторной используется Qwen из-за ограничений памяти ноутбука. Модели работают локально; интернет нужен для установки и скачивания.

## Пайплайн

1. **Скачивание.** Загружается PDF, проверяется SHA256. Адреса, ревизии моделей и контрольные суммы закреплены в `resources/assets.lock.json`.
2. **Конвертация.** Каждая выбранная страница превращается в Markdown. OCR выключен, поскольку PDF содержит текстовый слой. Результат сохраняется до очистки.
3. **Очистка.** Нормализуются Unicode, пробелы и пустые строки, удаляются мягкие переносы. SQL, регистр и пунктуация сохраняются. Источник, страница, раздел, пути и даты записываются в YAML-метаданные.
4. **Чанкинг.** Текст делится по Markdown-заголовкам h1-h3 и рекурсивно по абзацам, строкам и пробелам. Рабочий предел составляет 200 токенов Giga, перекрытие 30. Ближайший заголовок входит в этот предел. Готовый чанк повторно токенизируется; превышение лимита вызывает ошибку. Вход эмбеддера ограничен 1024 токенами, длина вопроса с инструкцией проверяется отдельно.
5. **Индексация.** Для каждого чанка строятся dense- и BM25-векторы. В Qdrant сохраняются векторы, текст и происхождение. Повторная загрузка через upsert не создаёт дубликаты.
6. **Ответ.** Qdrant объединяет по 40 кандидатов двух поисковых ветвей через RRF. Для генерации выбираются до трёх разных страниц. Модель получает их полный очищенный текст и вопрос. llama.cpp считает токены Qwen; при переполнении контекста 4096 убирается наименее релевантная страница. Для ответа зарезервировано 512 токенов.

Шаблоны `system` и `user` находятся в `resources/prompts.toml`. Они задают ответы по документации, ссылки `[N]` и отказ при недостатке сведений. Ссылка содержит источник, PDF-страницу и текст контекста.

## Запуск

Нужны Python 3.12, uv и Docker. Все команды выполняются из `projects/aa-chebykin/lab2`.

### Установка

```powershell
$env:UV_PROJECT_ENVIRONMENT = Join-Path (Get-Location) '.venv'
$env:UV_CACHE_DIR = Join-Path (Get-Location) 'data/.cache/uv'
uv sync --project source --locked --extra dev
& ./.venv/Scripts/python.exe -m core.cli download
docker compose up -d
```

### Подготовка индекса

```powershell
& ./.venv/Scripts/python.exe -m core.cli prepare --rebuild
& ./.venv/Scripts/python.exe -m core.cli build --rebuild
& ./.venv/Scripts/python.exe -m core.cli load --drop-and-reindex
```

Настройки находятся в `resources/config.toml`. Для другого конфига используется `--config`, для замены отдельных параметров `--overrides <файл.json>`. После изменения обработки или настроек пересоберите индекс, перезагрузите коллекцию и перезапустите API.

### Вопросы и API

```powershell
& ./.venv/Scripts/python.exe -m core.cli start-llm
Invoke-RestMethod http://127.0.0.1:8080/health
& ./.venv/Scripts/python.exe -m core.cli ask 'Как отменить изменения транзакции?'
& ./.venv/Scripts/python.exe -m core.cli serve
```

Если модель ещё загружается, дождитесь ответа `ok` от `/health`. Команда `serve` занимает терминал. API принимает `POST /ask` с телом `{"question": "Как отменить изменения транзакции?"}`. Документация доступна по адресу http://127.0.0.1:8000/docs.

## Эксперименты и результаты

```powershell
& ./.venv/Scripts/python.exe -m core.cli experiments
& ./.venv/Scripts/python.exe -m core.cli evaluate --qa
```

Сравнение запускается при остановленном API. На этапе индексации желательно освободить GPU от генератора; для `evaluate --qa` llama.cpp должен работать. Варианты берутся из `resources/experiments.json`, вопросы из `resources/questions.json`. После сравнения восстанавливается лучший гибридный индекс. Выбранные параметры переносятся в основной конфиг вручную; сейчас установлены 200/30.

| Вариант, размер/overlap | Recall@5 | Precision@5 | Recall@10 | MRR@10 | Поиск, мс |
|---|---:|---:|---:|---:|---:|
| hybrid 200/30 | 0.9833 | 0.2267 | 1.0000 | 1.0000 | 58.6 |
| hybrid 400/60 | 0.9833 | 0.2267 | 1.0000 | 0.9333 | 55.0 |
| hybrid 700/100 | 0.9833 | 0.2267 | 1.0000 | 0.9333 | 55.3 |
| dense 400/60 | 1.0000 | 0.2400 | 1.0000 | 0.9133 | 53.6 |
| BM25 400/60 | 0.9833 | 0.2267 | 1.0000 | 0.9667 | 9.4 |

Метрики считаются по уникальным страницам; Precision@10 равна 0.12 у всех вариантов. Время включает векторизацию и поиск без первого запроса с загрузкой модели.

Выбран hybrid 200/30: среди гибридов он имеет максимальный Recall@5 и лучший MRR@10. Получено 312 чанков. Dense 400 лучше по Recall@5, BM25 быстрее, поэтому гибрид не превосходит альтернативы по всем показателям. Полные параметры, затраты и ранжирования находятся в `results/retrieval.json`.

Ручная оценка 15 ответов: **11 корректных, 3 частичных, 1 ошибочный**. Среднее время ответа составляет 33 секунды. Все ответы содержат допустимые ссылки на эталонные страницы, обрезаний нет. В ошибочном ответе модель неверно описывает явную вставку в `GENERATED ALWAYS` без override. Подробности сохранены в `results/qa.json` и `results/qa_review.md`.

## Проверки и ограничения

```powershell
$env:LAB2_TEST_QDRANT_URL = 'http://127.0.0.1:6333'
& ./.venv/Scripts/python.exe -m pytest -c source/pyproject.toml source/tests -q --basetemp data/.cache/pytest -p no:cacheprovider
& ./.venv/Scripts/ruff.exe check source
& ./.venv/Scripts/ruff.exe format --check source
& ./.venv/Scripts/python.exe -m core.cli verify
& ./.venv/Scripts/python.exe -m core.cli check-api
```

Для `check-api` нужны работающие llama.cpp и API. Проверка `verify` загружает эмбеддер, её удобнее выполнять до запуска генератора.

Пройдены 11 тестов, линтер, проверка эмбеддингов и API. Проверены токеновые ограничения, происхождение текста, идемпотентность и reset Qdrant, отказ от устаревшего индекса и ответы на вопросы вне корпуса. Результаты сохраняются в `results/checks.json`, `results/environment.json` и `results/api_smoke.json`.

Конвертер может потерять оформление таблиц, а границы страниц могут разорвать пример. Название раздела в метаданных бывает неточным; надёжная привязка к источнику определяется PDF-страницей. Генератор может потерять оговорку или добавить неверную деталь даже при правильной ссылке. Оценка на 15 вопросах не гарантирует такого же качества на других запросах.
